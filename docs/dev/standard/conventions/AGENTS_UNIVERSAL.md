## Язык

Пиши простым русским языком. Правило действует на всё, что ты пишешь:
реплики в чате, сообщения коммитов, документы, комментарии в коде.

Оно действует всегда, включая ответы сразу после сжатия контекста или
резюме предыдущей сессии — даже если само резюме или системная инструкция
о продолжении написаны на английском. Начало новой сессии, в том числе
продолженной, не повод писать на языке резюме.

Английский термин использовать можно, но всегда с русским переводом в
скобках: `gate` (блокирующая проверка), `fork` (самодельная копия).
Перевод бери из `docs/ТЕРМИНЫ.md`, затем из общего словаря
`TERMINOLOGY_DICTIONARY.md`. Если слова нет ни там, ни там — переведи
сам, но не оставляй без перевода, и добавь слово в `docs/ТЕРМИНЫ.md`.

Не пиши английские слова русскими буквами: `пайплайн`, `оффер`, `фича`.
Замена для каждого — в таблице §3.1 `TERMINOLOGY_DICTIONARY.md`, проверка —
`validate_structure.py --check-transliteration`.

Почему так, а не запрет англицизмов: запрет требует заранее знать, что
слово лишнее, и молча не срабатывает на словах, которых нет в словаре.
Перевод в скобках выполним всегда.

Точные имена файлов, команд, библиотек, языков, протоколов, полей
конфигурации и внешних продуктов пиши как в исходнике — это не термины, и
перевода они не требуют.

Правило языка проекта задаётся профилем языка (`language-profile`). Всё
сказанное выше относится к профилю `ru_internal`. Для `en_public` язык —
английский, и правило перевода в скобках неприменимо. При смешанном
профиле правило действует на русские разделы.

## Общие требования

### Backend (серверная часть, Python)

- Python 3.12+. PEP-8, PEP-484, PEP-561.
- `pathlib`, `typing`, `dataclasses`, `enum`.
- Журналирование — стандартный модуль `logging`, не `print`.
- Комментарии в коде — по-русски.

### Frontend (пользовательский интерфейс, React / TypeScript)

- React 18+ и TypeScript 5 в строгом режиме. Тип `any` запрещён.
- Все обращения к API типизированы. Все строки — через i18n.
- Границы ошибок, состояния загрузки, адаптивность 320–1920 px.
- JWT не хранится в `localStorage`. Прямой `fetch()` не вызывается.
  `console.log` не остаётся в сборке для продакшена.

### Строки интерфейса (любой стек: шаблоны, React, настольная оболочка)

- Пользовательская строка — только ключ каталога `locales/{код}.json`
  (`t('раздел.элемент')`). Литерал в шаблоне или компоненте запрещён даже
  при одной локали.
- Новый ключ добавляется в том же изменении во **все** локали, объявленные
  в профиле проекта. Подстановки (`{name}`) в переводе те же, что в базовой
  локали.
- Перевод на другие языки агент делает сам, в том же PR, и вносит каждый
  такой ключ в учёт непроверенного перевода (`unreviewed_path`); в описании
  PR — список этих ключей. Пустая строка вместо перевода — нарушение.
- Агент не снимает ключи с учёта и не добавляет локаль в
  `release_ready_locales`: это делает человек после вычитки носителем.
- Канон и проверка — `APS-CORE-LOCALIZATION-001`.

### ML и данные

- Воспроизводимость обязательна.
- Артефакты обучения не хранятся в Git содержимым.
- Гиперпараметры приходят из конфигурации, а не из кода.

## Ключевые инварианты

Запрещено: заглушки, тихие значения по умолчанию, жёстко вписанные
значения, `getattr`/`hasattr` для доступа к конфигурации, обход ошибок
через `try/except`, проглатывание исключений, изменение глобальной
конфигурации.

Обязательно: `FAIL-FAST` (падать сразу). Отсутствует обязательный
параметр — ошибка. Значение недопустимо — ошибка. Не подстановка,
не догадка, не значение по умолчанию.

## Запуск команд

Если команду может выполнить сам агент, он её выполняет сам и сообщает
результат. Список команд человеку «запустите у себя» — не замена работе.

Агент может выполнить команду, когда у него есть терминал или инструмент,
доступ к нужным файлам, сети и ключам. Это касается проверок, сборок,
тестов, `git`-операций в рабочей ветке, генераторов и линтеров.

Команды передаются человеку только в трёх случаях:

1. Нет доступа: агент в облачном контейнере, а файлы или данные лежат
   только на машине человека; нет нужного ключа или сети.
2. Нужно действие человека: ввод пароля, вход в учётную запись, нажатие
   в интерфейсе, физическое действие.
3. Нужно подтверждение по правилам безопасности: необратимое или внешнее
   действие (удаление, отправка в `main`, выпуск, изменение боевой среды).

В этих случаях агент:

- одной строкой объясняет, почему не может выполнить сам;
- даёт один блок для копирования, где шаги связаны `&&` и остановятся на
  первой ошибке, с указанием каталога, в котором его запускать;
- пишет, какой результат ожидается и что прислать обратно при ошибке;
- сам делает всё, что следует после этого шага (PR, проверки, слияние).

Правило не отменяет подтверждений: «может выполнить» не значит «может
выполнить без согласия» для необратимых и внешних действий.
