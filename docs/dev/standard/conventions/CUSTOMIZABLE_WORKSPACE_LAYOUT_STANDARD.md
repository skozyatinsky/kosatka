# Стандарт настраиваемого рабочего пространства и возврата настроек по умолчанию

> Редакция 2. Канонический стандарт построения модульных рабочих столов:
> витрины подбора, кабинеты учёта клиентов, карточки расчётов, панели менеджера.
> Единственная допустимая реализация — контроллер `sortable_sections.js`
> из `_library/agent_configs/global/web_assets/workspace_layout/`.

## 1. Назначение и область применения

Рабочие места менеджеров различаются по должностным ролям:

- закупщик начинает с каскада поставщиков и порогов наценки;
- тендерный специалист — с загрузки файлов технического задания и сверки с реестрами;
- менеджер прямых продаж — с карточки контрагента и баланса взаиморасчётов.

Рабочий стол состоит из независимых секций. Пользователь переставляет их под себя.
Порядок запоминается в браузере. Пользователь в любой момент возвращает исходный порядок
и исходные значения форм.

Стандарт обязателен для всех проектов экосистемы. Самодельные скрипты перетаскивания
в отдельных шаблонах запрещены. Проект копирует `sortable_sections.js` в свою статику
**без изменений** (по образцу `web_assets/tooltip/`) и не правит копию: любое изменение
вносится в библиотеку, проходит приёмочные тесты и раскатывается во все проекты.

## 2. Термины

| Термин | Определение |
|---|---|
| Рабочее пространство | Контейнер, в котором пользователь переставляет секции |
| Секция | Прямой дочерний элемент контейнера с постоянным уникальным `id` |
| Ручка | Элемент захвата секции мышью или клавиатурой |
| Эталонный порядок | Последовательность секций, заданная разработчиком |
| Локальное хранилище | Хранилище браузера (`localStorage`), доступное только на этом устройстве |
| Сдвиг макета | Видимое смещение блоков страницы после её первой отрисовки |

## 3. Контракт разметки

| Атрибут | Где | Назначение |
|---|---|---|
| `data-sortable-container="ид"` | контейнер | Идентификатор экрана. Уникален в пределах проекта |
| `data-sortable-section` | секция | Признак секции. Секция обязана иметь `id` и быть прямым потомком контейнера |
| `data-section-title="..."` | секция | Название для программ экранного чтения. По умолчанию берётся из `aria-label`, заголовка или `id` |
| `data-default-order="a,b,c"` | контейнер | Эталонный порядок. Если не задан, используется порядок разметки |
| `data-storage-namespace="crm"` | контейнер | Пространство имён проекта. Обязательно. Допустима замена на `<meta name="workspace-storage-namespace">` |
| `data-storage-scope="ид"` | контейнер | Непрозрачный идентификатор пользователя. Обязателен, если рабочее место может быть общим |
| `data-layout-version="1"` | контейнер | Версия компоновки. Повышается для принудительного сброса настроек всех пользователей |
| `data-legacy-storage-key="..."` | контейнер | Старый ключ для однократного переноса данных |
| `data-layout-pending` | контейнер | Скрывает контейнер до перестановки. Снимается контроллером |
| `data-drag-handle` | ручка | Захват мышью и клавиатурой. Элемент `<button type="button">` |
| `data-move-section="up\|down"` | кнопка | Перемещение на одну позицию |
| `data-reset-layout="ид"` | кнопка | Возврат порядка по умолчанию. Допускается вне контейнера |
| `data-reset-form="ид_формы"` | кнопка | Возврат значений формы к исходным (`form.reset()`) |

Идентификаторы секций — часть сохранённых настроек. Переименование секции приравнивается
к её удалению и добавлению новой.

## 4. Хранение настроек

### 4.1. Ключ

`{пространство}:layout:{область}:{экран}`, например `crm:layout:u4821:dashboard`.
Недопустимые символы заменяются на `_`. Префикс `bp_layout_` объявляется устаревшим
и переносится через `data-legacy-storage-key`.

В области хранения запрещено размещать персональные данные: допускается только
непрозрачный внутренний идентификатор.

### 4.2. Формат

```json
{ "v": 1, "layout": "1", "order": ["sec-a", "sec-b"] }
```

- `v` — версия формата хранения. Меняется только вместе с контроллером.
- `layout` — значение `data-layout-version`.
- `order` — массив строк не длиннее 200 элементов.

Запись с другой `v`, другой `layout` или неверной структурой удаляется,
и показывается эталонный порядок.

### 4.3. Согласование с фактическим составом секций

При каждой загрузке и после каждой подмены содержимого:

1. Идентификаторы, которых нет в разметке, и повторы отбрасываются.
2. Каждая секция, которой нет в сохранённом порядке, ставится сразу за ближайшей
   предшествующей ей в разметке секцией. Если такой нет — в начало.
3. Если результат отличается от сохранённого, он записывается обратно.

Секции, скрытые правами доступа, **не удаляются из разметки**, а скрываются
атрибутом `hidden`. Иначе их позиция теряется при следующем сохранении.

## 5. Режимы ввода

| Режим | Условие | Возможности |
|---|---|---|
| `drag` | ширина не менее 768 пикселей и точный указатель | перетаскивание мышью, клавиатура, кнопки ↑/↓ |
| `buttons` | остальные устройства | клавиатура и кнопки ↑/↓; ручка скрыта |

Контроллер выставляет контейнеру `data-layout-mode` и следит за изменением условия.
Сенсорные касания не обрабатываются: нативное перетаскивание на сенсорных экранах
не поддерживается и мешает прокрутке.

Перетаскивание можно отменить клавишей Escape или сбросом вне контейнера:
порядок возвращается к состоянию до начала. Сохранение происходит только после
успешного сброса секции в контейнер.

## 6. Доступность

1. Ручка — `<button type="button">` с `aria-pressed` (состояние захвата), понятным
   `aria-label` и `aria-describedby` на скрытую подсказку.
2. Атрибуты `aria-grabbed` и `aria-dropeffect` не применяются: они исключены из WAI-ARIA 1.2.
3. Управление с клавиатуры: пробел или Enter — захват и фиксация; ↑/↓ — шаг; Home и End —
   в начало и в конец; Escape — отмена. Потеря фокуса фиксирует текущее положение.
4. Каждое действие объявляется через область `role="status"` с `aria-live="polite"`:
   «Секция «Поставщики»: позиция 2 из 5».
5. Кнопки ↑/↓ на краях получают `aria-disabled="true"`, а не `disabled`, чтобы сохранять фокус.
6. После перестановки фокус возвращается на тот же элемент.
7. Анимации перестановки должны учитывать `prefers-reduced-motion`.

## 7. Производительность и отсутствие сдвига макета

1. Один набор слушателей на контейнер (делегирование), а не на каждую секцию.
   Это работает после подмены содержимого через HTMX.
2. Событие `dragover` только запоминает координату. Вычисления выполняются не чаще
   одного раза за кадр (`requestAnimationFrame`).
3. Целевая позиция определяется по середине секций без учёта перетаскиваемой.
4. Шаблон обязан задавать `data-layout-pending` и подключать минимальный CSS (см. §10).
   Контейнер скрыт с сохранением места до перестановки. Аварийное открытие через
   1 секунду защищает от отказа скрипта.

## 8. Отказоустойчивость

1. Каждый контейнер инициализируется отдельно. Сбой одного не затрагивает остальные.
2. Любой сбой обработчика пишется в консоль и не прерывает страницу.
3. Слушатели стоят на контейнере в фазе перехвата. Сторонний скрипт внутри секции
   не может отключить управление, вызвав `stopPropagation` или упав.
4. Недоступное или переполненное локальное хранилище не прерывает работу:
   порядок действует до перезагрузки страницы.
5. Секции без `id` и вложенные контейнеры игнорируются.
6. Атрибут `data-layout-pending` снимается всегда, даже при сбое инициализации.

## 9. События и программный интерфейс

- Событие `workspace:layout-change` (всплывает от контейнера). В `detail`:
  `containerId`, `order`, `reason` (`drag`, `keyboard`, `button`, `reset`).
- `WorkspaceLayout.init(корень)` — инициализация вновь вставленного фрагмента.
  Вызывается автоматически по `htmx:load`.
- `WorkspaceLayout.reset(ид)`, `WorkspaceLayout.order(ид)`, `WorkspaceLayout.version`.
- Изменение в другой вкладке применяется автоматически (событие `storage`).

## 10. Минимальная реализация шаблона

```html
<div id="ws-dashboard" data-sortable-container="dashboard"
     data-storage-namespace="crm" data-storage-scope="{{ user.opaque_id }}"
     data-layout-version="1" data-default-order="sec-a,sec-b" data-layout-pending>
  <section id="sec-a" data-sortable-section data-section-title="Поставщики">
    <button type="button" data-drag-handle>⠿</button>
    <button type="button" data-move-section="up">↑</button>
    <button type="button" data-move-section="down">↓</button>
    ...
  </section>
</div>
<button type="button" data-reset-layout="dashboard">Вернуть порядок по умолчанию</button>
```

Общий CSS проекта:

```css
[data-sortable-container][data-layout-pending] {
  visibility: hidden;
  animation: workspace-layout-reveal 0s linear 1s forwards;
}
@keyframes workspace-layout-reveal { to { visibility: visible; } }
[data-layout-mode="buttons"] [data-drag-handle] { display: none; }
[data-sortable-section][data-sortable-dragging] { opacity: .4; }
[data-move-section][aria-disabled="true"] { opacity: .4; cursor: not-allowed; }
```

## 11. Приёмка

Автоматические проверки лежат в `web_assets/workspace_layout/tests/` и выполняются
при каждом изменении контроллера:

- [ ] Новая секция встаёт на ожидаемое место при ранее сохранённом порядке.
- [ ] Удалённая секция не оставляет следов в хранилище.
- [ ] Повышение `data-layout-version` сбрасывает порядок.
- [ ] Ключи двух проектов на одном домене не пересекаются.
- [ ] Ширина менее 768 пикселей: ручка скрыта, ↑/↓ работают, прокрутка не затронута.
- [ ] Полный цикл только с клавиатуры, объявления доступны программам экранного чтения.
- [ ] Escape и сброс вне контейнера возвращают прежний порядок.
- [ ] Страница не показывает «прыжка» блоков при загрузке.
- [ ] Ошибка в стороннем скрипте внутри секции не отключает управление.
- [ ] Недоступное локальное хранилище не вызывает ошибок на странице.

Вручную, перед выпуском новой версии контроллера: перетаскивание настоящей мышью
в Chrome, Firefox и Safari; проверка с VoiceOver и NVDA. Автоматический тест
перетаскивания использует синтетические события, потому что эмуляция указателя
в Playwright не доставляет событие `drop`, если во время перетаскивания переставлен
исходный узел.

Проект при подключении экрана проверяет свою разметку: уникальные `id` секций,
заданные `data-storage-namespace` и `data-storage-scope`, наличие `data-layout-pending`
и общего CSS.

## 12. Запреты

- Собственные скрипты перетаскивания и изменённые копии контроллера.
- Персональные данные в ключе или значении хранилища.
- Секции, не являющиеся прямыми потомками контейнера.
- Динамически генерируемые случайные `id` секций.
- Классы оформления в JavaScript: состояние выражается атрибутами.
